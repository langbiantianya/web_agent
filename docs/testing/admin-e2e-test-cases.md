# 管理后台完整验收用例（按钮级）

> [`e2e-agent-skill-mcp-workflow.md`](e2e-agent-skill-mcp-workflow.md)。

测试环境：`http://192.168.5.19:8001/admin/`
部署：`192.168.5.19` 的 `/docker/web-agent-stack`，
`docker compose -f deploy/docker-compose.stack.yml --env-file .env up -d --build`

> **环境约定**：管理端**必须**连自己的库（`.env` 里的 `ADMIN_DATABASE_URL` → PostgreSQL `webagent_admin`），
> 与客户端的 MySQL `webagent` 分开。本轮之前 compose 的 `environment:` 把 `.env` 的值覆盖成空串，
> 管理端静默地退回客户端主库——见 UX 评审文档的 **UX-24**。
> 部署后用 `docker exec webagent-admin env | grep ADMIN_DATABASE_URL` 复核。

测试数据统一使用 `e2e-20261110-<随机值>` 前缀。删除用例只操作本轮创建的临时数据；
内置浏览器在执行删除、权限变更和账号变更前仍应逐项确认。

> **触发方式**：所有按钮一律用**鼠标**触发（`click` / `selectOption` / `fill`）。
> `evaluate` 只用于**只读**检查（读 DOM 文本、量溢出），**不用于**代替点击。

### 本轮测试环境的两点说明

1. **内置浏览器的输入管道在中途卡住**：原标签页上点了一次「编辑内容尚未保存，
   确定要离开吗？」的原生确认框之后，该标签页的 CDP 会话就不再响应，
   新建的标签页能读 DOM、但收不到鼠标事件。因此最后两项（导航链接的点击、
   编辑面板「关闭」在**有未保存改动**时的行为）无法在本轮末尾复测——
   这两项在**同一轮早些时候**已经用鼠标验证过：导航链接（概览页的「编辑页面权限」
   「查看 Casbin 角色」、各行的「编辑连接 / 编辑身份提供方 / 编辑技能 / 编辑智能体」）
   点击后都正常跳转；OAuth 提供方编辑面板的「关闭」点击后正常回到列表页；
   而智能体编辑面板在**填过表单**之后点「关闭」被留在原页、`data-edit-dirty`
   置为 `1`——这正是「未保存离开保护」该有的行为。
2. **本地 venv 缺 `pywin32` 的 `_win32sysloader.dll`**：`tests/test_mcp_e2e.py`
   在本机导入 `mcp.server.stdio` 就失败，属于环境问题，与本轮改动无关。

### 本轮实测确认的修复

- **UX-33**：stdio 注册失败时，字段级错误落在 **`command`** 上
  （`err-mcp-create-command`），中文文案「stdio 命令无法启动。」；
  HTTP 注册失败仍然落在 `url` 上，中文文案「HTTP 地址无法校验。」。
- **UX-34**：「刷新工具」连不上时提示「连不上这台 MCP 服务器，或读不到它的
  工具目录。请检查地址或命令后重试。」——不再是一句「无法完成操作。」。
- **UX-35**：「保存偏好设置」后出现「偏好设置已保存。」；平台管理员撤销删除后
  出现「资源已恢复。」
- **UX-36**：`?source=builtin&ok=true` 重新打开审计页，两个下拉框**停在已生效
  的条件上**，与 URL 一致。
- **UX-37**：中文界面下探测失败显示「失败 · API 密钥被拒绝，请检查密钥及其所属账号。」，
  折叠的「排查指引」正文也是中文。
- **UX-38**：错误提示条渲染为 `flash warn`（与成功的 `flash info` 样式可区分）。
- **UX-39**：`admin_deleted_resource` 从 `app.models` 导出后，三种方言的表一致性
  断言不再受 import 顺序影响（`test_postgres_compat` 全量跑通过）。
- **UX-40**：三处漏 import 已修复——「保存端点」「智能体禁用 / 启用」
  「工作流禁用 / 启用」现在都返回 303 并提示「更改已保存。」/「资源状态已更新。」，
  不再是 500；同时新增静态守卫用例，防止同类漏 import 再犯。
- 确认对话框：标题写明**具体对象名**，技能归档的按钮文案是「归档」而不是「删除」，
  OAuth 提供方删除明确写「此操作无法撤销」。
- 删除 → 撤销的往返在浏览器里逐个验证通过：MCP 服务器、智能体、平台超级管理员。
- 被工作流引用的智能体：禁用与删除按钮都**禁用**，`title` 写明引用者。
- 内置角色（operator / tenant_admin / viewer）的删除按钮**禁用**并写明原因。
- 工作流保存失败**留在画布上**，错误条列出「节点 step2 是 agent 类型，必须指定
  agentCode」「以下节点从 entry 走不到（孤立节点）：step2」，节点不丢。
- 预设下拉**真的**把编码 / 名称 / 基础 URL 填进创建表单（不是过滤表单）。
- 列表页的搜索与排序**回显**到控件上，URL 可分享。

| 用例 | 步骤 | 期望 |
| --- | --- | --- |
| NAV-01 | 打开任意长页面（页面权限 / 角色与权限），把页面往下滚 700px | 左侧导航**停在原地**，上沿紧贴顶栏下沿（间距 0px），不跟着内容滚走 |
| NAV-02 | 滚动后点侧边栏里的任意一个菜单项 | 导航本身仍然可点，点击后正常跳转 |
| NAV-03 | 换到 Fluent / Cloudscape / Material 三个主题（深浅各测）分别滚动 | 三种主题下侧边栏都吸附在顶栏下沿；顶栏高度分别按 56px / 48px / 64px 对齐 |
| NAV-04 | 视口调到 390px，点开顶部「菜单」 | 手机端侧边栏回到普通文档流（`position: static`），菜单能展开、14 个入口都在 |
| NAV-05 | 视口调到 390px 后往下滚 | 手机端导航**不吸附**（它本来就是顶部的一整块） |

### 勾选框 / 单选框形状（UX-49）

| 用例 | 步骤 | 期望 |
| --- | --- | --- |
| CB-01 | 打开页面权限页，展开「全局默认」权限手风琴 | 每个权限项前面的勾选框是规规矩矩的 **16×16px 方形**，勾号不变形 |
| CB-02 | 打开组件权限 / 角色与权限，同样展开权限矩阵 | 同上；勾选框不会被拉成竖条 |
| CB-03 | 打开智能体页，看「能力」里的技能 / 工具勾选框 | 同上；勾选框宽度不随文字长短变化 |
| CB-04 | 打开外观页，看三个主题卡片 | 主题卡片里的单选框是视觉隐藏的 1×1（不是 1×44 的细针）；**点卡片本身**能切换主题 |
| CB-05 | 用脚本扫一遍 14 个管理页 | 所有可见的勾选框 / 单选框尺寸都 ≤ 20×20px，没有被拉长的 |
| CB-06 | 点一个勾选框 | 能正常勾上 / 取消，勾选状态回显正确 |
