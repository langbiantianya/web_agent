# 管理后台 UI 布局与主题校验记录（2026-11-11 第五轮）

本轮**只做校验、只记录问题，不做修复**。等确认后再统一动手。

## 校验范围

用内置浏览器（`iab`）逐一点击操作，**没有用 JS 触发任何按钮**——主题切换、
菜单导航、创建/编辑面板展开、删除确认对话框全部是鼠标点击出来的。

| 维度 | 取值 |
| --- | --- |
| 主题 | Fluent Design / AWS Cloudscape / Google Material（3 种） |
| 颜色模式 | 浅色 / 深色（各主题 × 2 = 6 种组合） |
| 密度 | 舒适 / 紧凑（另测 3 组） |
| 页面 | 14 个管理页（概览、页面权限、组件权限、角色与权限、OAuth 角色映射、工作流、智能体、技能、MCP 服务器、LLM 端点、OAuth 身份提供方、平台超级管理员、外观、工具审计） |
| 子功能 | 24 个子视图：8 个「创建资源」表单、6 个行内编辑器、2 个删除确认对话框、3 个权限手风琴（全局默认 / 新增租户覆盖 / 编辑权限 / 角色继承）、1 个审计筛选、1 个 MCP 刷新 |
| 视口 | 桌面 1531×676、平板 768×1024、手机 390×844 |

合计 **456 条**页面/子视图快照（`results.jsonl`），另有 344 张截图。

## 结论速览

- **布局结构整体是健康的**：所有 6 种主题组合 × 38 个视图下，**没有一处**
  元素溢出视口、没有文字被裁切、没有整页横向滚动条。手机端的表格
  确实是窄的，但都规规矩矩落在 `.table-scroll`（`overflow-x:auto`）里
  横向滚动，属于设计预期。
- **问题集中在两处**：① 深色主题下几个关键控件的**前景/背景对比度**
  达不到 WCAG AA（4.5:1）；② 768px 平板宽度下**表格表头被压成竖排**、
  若干按钮文字**折行**。

## 问题清单

严重度沿用既有口径：**P0** 数据错误/安全误操作/无法完成任务；
**P1** 明显增加操作成本或容易误判；**P2** 可用性、可访问性或视觉一致性。

### LAY-01 · P1 · 深色主题下「删除 / 归档」危险按钮文字几乎看不清

- **位置**：所有资源列表行内操作按钮（工作流、智能体、技能、MCP、LLM、
  OAuth 提供方、平台超管、OAuth 角色映射），共 13 个页面。
- **现象**：深色主题（三种主题的深色模式全部复现）里
  `--color-danger` 被覆盖成浅红色 `#ff8b80`，但 `.btn-danger` 的文字色
  仍写死 `color: #ffffff`，于是变成**白字压在浅红底**上。
  实测对比度 **2.27 : 1**（WCAG AA 要求 4.5:1）。
  浅色主题下同一个按钮是 `#d13438` 底白字，对比度 4.93:1，正常。
- **根因**：`services/admin_web/static/admin.css` 的 `.btn-danger` 硬编码
  `color: #ffffff`，没有随 `--color-danger` 一起翻转。深色模式把底色调亮
  了，文字色没跟着调。
- **建议**：`.btn-danger` 的文字色改用变量（如 `--color-danger-text`），
  在三个主题的深色分支里给一个深色值（浅红底配深字才达 4.5:1）。
- **影响范围**：深色模式 13 个页面 × 全部危险按钮。**P1**，因为这是
  不可逆操作（删除）的主按钮，看不清就容易点错。

### LAY-02 · P1 · Cloudscape 深色主题下侧边栏分组标题几乎不可读

- **位置**：侧边栏分组标题（概览 / 访问控制 / 资源 / 安全 / 设置 / 运维），
  **全部 38 个视图**都复现。
- **现象**：`html[data-theme="cloudscape"] .nav-group-title` 的颜色
  **硬编码**为 `#687078`，而 Cloudscape 深色模式的侧边栏底色是
  `#0f1823`——这条硬编码颜色在深浅两种模式下都一样，于是深色下对比度
  只有 **3.55 : 1**，低于 4.5:1。
- **根因**：同文件第 1508-1514 行，`color: #687078` 写死；该主题的
  `--color-sidebar-muted` 在深色下是 `#d6d6d6`，本可以复用。
- **建议**：改用 `var(--color-sidebar-muted)`，或在深色分支里单独覆盖。
- **对比参照**：Fluent 与 Material 的同名元素用的是
  `var(--color-sidebar-muted)`，所以只有 Cloudscape 有这个问题。

### LAY-03 · P1 · 768px 平板宽度下表格表头被压成「一个汉字一行」

- **位置**：12 个带表格的页面（页面权限、OAuth 角色映射、工作流、智能体、
  技能、MCP 服务器、LLM 端点、OAuth 身份提供方、平台超管、工具审计、
  组件权限、角色与权限）。
- **现象**：平板宽度（768×1024）下侧边栏仍占 220px，内容区只剩约 500px，
  表格列被挤到 38–90px 宽。**表头逐字换行**：「被智能体使用」变成 6 行
  竖排（每行一个字）、「传输方式」「状态」「版本」各 4–6 行，
  表头行高被撑到 138px。
- **根因**：`admin.css` 第 615-618 行 `.data-table { width: 100% }`，
  且 `min-width` 为 0。`.table-scroll` 虽有 `overflow-x:auto`，
  但表格自己会**收缩到容器宽度**而不是撑出最小宽度，于是滚动条永远
  不会出现，横向滚动机制形同虚设。
- **建议**：给 `.data-table` 设一个 `min-width`（按列数给合理下限），
  让它在窄屏撑破容器、由 `.table-scroll` 负责横向滚动；或者在 ≤1199px
  时启用卡片式行布局（与既有 UX-12 的方向一致）。
- **注**：手机宽度（390px）下表现正常——表格正常横向滚动，表头只是
  两行，没有竖排。

### LAY-04 · P2 · 「保存」按钮在 OAuth 角色映射页折成两行

- **位置**：`/admin/access/mappings`，行内编辑表单的「保存」按钮。
- **现象**：按钮宽 44–61px、高 48–57px，文字「保存」被拆成「保」/「存」
  两行。**三种主题 × 深浅两色 × 桌面宽度全部复现**（宽度随主题变化：
  Fluent 44px、Cloudscape 51px、Material 61px），手机宽度下「删除」按钮
  也折行（62px / 57px）。
- **根因**：`.mapping-actions` 是 `display:flex; min-width:250px`，
  但按钮本身 `flex-shrink:1`，在 547px 的单元格里被压扁；
  `.btn` 又没有 `white-space:nowrap`，所以文字直接折行。
- **建议**：`.btn` 补 `white-space: nowrap`；`.mapping-actions` 里的
  按钮给 `flex-shrink: 0`。
- **视觉证据**：`audit/zoom_mappings_save.jpg`（按钮内「保」「存」上下
  排列）。

### LAY-05 · P2 · 工作流编辑器里「入口」标记与节点端口圆圈重叠

- **位置**：`/admin/workflows/{code}` 画布，入口节点左侧的「入口」文字标记。
- **现象**：标记文字的右边缘 x=585，端口圆圈左边缘 x=587，
  **两者重叠 22px**（整段文字宽度）。截图里「入口」两字的右半被
  蓝色圆环压住，视觉上读作「入口○」糊成一团。
- **根因**：`workflow-editor.js` 第 430-437 行把标记放在
  `x: -8, text-anchor: "end"`；但节点的 `<g>` 变换是
  `translate(40, 40)`，而 `rect.body` 宽度 200 起点 x=0——标记的
  锚点被体块的起点顶掉了，文字实际从 x=563 起画，正好压在
  `port-in`（cx=0, r=6）上。
- **建议**：把标记锚点改到体块左边缘之外（`x: -12` 或更负），
  并给节点留出左侧内边距，避免与端口圆圈相撞。
- **视觉证据**：`audit/zoom_entry_live.jpg`（「入口」右半被圆环覆盖）。

### LAY-06 · P2 · Cloudscape 浅色主题下链接类文字对比度差 0.47

- **位置**：概览页的三个快捷操作卡片链接（编辑页面权限 / 编辑组件权限 /
  查看 Casbin 角色）、权限页的「全局默认」「1 项权限」「新增租户覆盖」
  「推荐权限」标签、智能体页的「技能」「MCP 服务器」内联链接。
- **现象**：Cloudscape 浅色主题的 `--color-accent` 是 `#0972d3`，
  在 `--color-bg-subtle`（`#e9ebed`）上只有 **4.03 : 1**，差一点点
  到 4.5:1。深浅两种模式只有**浅色**触发。
- **根因**：Cloudscape 浅色的 accent 色值本身与它的 subtle 底色
  组合后余量不足；Fluent（5.16:1）与 Material 未触发。
- **建议**：把 Cloudscape 浅色 `--color-accent` 压深一档（如 `#0a5fb0`
  一类），或对这些标签改用 `--color-accent-text`。

### LAY-07 · P2 · 深色主题下「被工作流引用」「工具不存在」告警文字过暗

- **位置**：智能体列表的「被工作流引用：xxx」提示、LLM 列表的
  「被智能体使用：xxx」提示、智能体能力区的 `ghost_tool · 工具不存在`
  徽章。
- **现象**：告警色 `#b45309`（橙褐）在深色底上对比度仅
  **2.90:1**（Fluent 深色）/ 3.42–3.46:1（Material、Cloudscape 深色），
  都低于 4.5:1。
- **根因**：`.warning-text` 与 `.capability-suggestion.is-missing` 用的是
  `var(--color-warning-text, #b45309)`——这个变量**在 CSS 里从未被定义过**
  （`grep` 全文只有 fallback 值），所以三个主题的深浅模式**一律**回退到
  浅色模式那个深橙褐 `#b45309`，在深色底上自然发闷。
- **建议**：为各主题的深色模式补上 `--color-warning-text`
  （浅底用深橙、深底用亮橙），或直接引用 `--color-warning` 并按模式取值。

## 改了什么

### LAY-01 · 深色模式危险按钮对比度

`admin.css` 新增一个跟随主题的文字色变量：

- `:root` → `--color-danger-text: #ffffff;`
- `html[data-color-mode="dark"]` → `--color-danger-text: #2b0a00;`
- `@media (prefers-color-scheme: dark) html[data-color-mode="system"]`
  → 同上

`.btn-danger` 的文字色从写死的 `#ffffff` 改成 `var(--color-danger-text)`。

| 模式 | 底色 | 文字色 | 对比度 |
| --- | --- | --- | --- |
| 浅色 | `#d13438` | `#ffffff` | 4.93 : 1 |
| 深色 | `#ff8b80` | `#2b0a00` | **8.08 : 1**（修复前 2.27 : 1） |

三个主题的深色分支都**没有**单独覆盖 `--color-danger`，所以通用深色规则
对三者同时生效，不需要逐主题改。

### LAY-02 · Cloudscape 深色侧边栏分组标题

`html[data-theme="cloudscape"] .nav-group-title` 的 `color: #687078`
改成 `var(--color-sidebar-muted)`。Cloudscape 深色下该变量取通用深色块的
`#aab4c0`，在侧边栏底色 `#0f1823` 上是 **8.51 : 1**（修复前 3.55 : 1）。
Fluent / Material 本来就是用这个变量，所以三主题表现一致了。

### LAY-03 · 平板宽度的卡片式表格

按决定做的是**卡片**，不是简单加 `min-width`：

- `admin-ui.js` 新增 `bindTableLabels()`：按 `thead` 的列名给每个 `<td>`
  打上 `data-label`（列数对不上的空状态行跳过）。
- `admin.css` 新增 `@media (min-width: 768px) and (max-width: 1199px)`：
  隐藏 `thead`，每行变成一张卡片（边框 + 圆角 + 阴影），每格用
  `td::before { content: attr(data-label) }` 显示列名，值列占满剩余宽度。
- ≤767px 的手机端**保持原样**（`min-width: 720px` + 首列吸附 + 横向滚动），
  上一轮已经确认那是设计预期。

另外补了一条与卡片无关、但同样属于 LAY-03 的根因修复：
`.data-table th { white-space: nowrap }`。手机宽度下表头虽然不再被压成
「一个汉字一行」，但「被工作流使用」这类表头仍会折成 2–3 行；不折行之后
列宽由表头撑开，手机端照旧在 `.table-scroll` 里横向滚动。

### LAY-04 · 「保存」按钮折行

- `.btn` 增加 `white-space: nowrap`——按钮文字一律不折行。
- `.mapping-actions` 增加 `flex-wrap: wrap`，按钮 `flex: 0 0 auto`：
  放不下就换行，不再把按钮压扁。
- `.mapping-actions input[name="role_code"]` 给出 `flex: 0 1 220px`：
  输入框默认 `width: 100%`，会把整行占满、把「保存」挤到下一行。

实测：按钮 50×28px、单行，与输入框同一行。

### LAY-05 · 「入口」标记与端口圆圈

**先更正上一轮的一处测量错误**：文档里写的「重叠 22px」不对，实际是
标记右沿 x=565、圆圈左沿 x=567，**只差 2px**——没有重叠，但视觉上贴在一起。

改法：把标记从节点**左边中点**（`y: NODE_HEIGHT/2 + 4`）挪到**左上角**
（`x: -10, y: 18`），也就是徽标那一行的高度。圆圈在左边中点（cy=36），
标记基线在 18，竖直方向彻底分开。

| 组合（3 主题 × 深浅 × 1531/768） | 与圆圈的竖直间距 | 与圆圈的横向间距 |
| --- | --- | --- |
| 修复后（12 个组合全部一致） | **10px** | 4px |

# 第七轮：左侧导航固定 + 勾选框形状（2026-11-11）

这一轮是用户直接指出的两个问题，都不是上一轮清单里的条目。

## LAY-08 · P2 · 页面滚动时左侧导航跟着一起滚走

- **位置**：管理端所有页面（`aside.sidebar`）。
- **现象**：内容区往下滑，左侧导航栏会跟着一起往上跑；长页面（比如
  「页面权限」的权限矩阵）下滑到一半就看不到导航了，想换页面得先滚回顶部。
- **根因**：`.admin-layout` 只是一个普通的两列网格，侧边栏是普通的网格项，
  页面滚动时它就跟着文档一起动。
- **改法**：
  - 新增 `--topbar-height` 变量（按主题给出实际高度：Fluent 56px、
    Cloudscape 48px、Material 64px），侧边栏吸附在顶栏下沿；
  - `.sidebar` 改成 `position: sticky; top: var(--topbar-height)`，
    并加 `align-self: start`——**这一条不能省**：网格项默认会被拉成整行
    高度，拉满了就吸附不动了；
  - `max-height: calc(100vh - var(--topbar-height))` + `overflow-y: auto`：
    导航本身比一屏还长时，它自己内部滚动，不再把整页撑长；
  - 手机端（≤767px）侧边栏是顶部的移动导航，改回 `position: static`。
- **实测**（滚动 700px 后）：

  | 主题 | 顶栏下沿 | 侧边栏上沿 | 间距 | 侧边栏下沿 |
  | --- | --- | --- | --- | --- |
  | Fluent | 56 | 56 | 0 | 676（= 视口高） |
  | Cloudscape | 48 | 48 | 0 | 676 |
  | Material | 64 | 64 | 0 | 676 |

  深浅两种模式各测一遍，6 种组合全部吻合。

## LAY-09 · P2 · 勾选框被拉成奇怪的锥形

- **位置**：所有带勾选框的地方——权限矩阵（页面权限 / 组件权限 /
  角色与权限，共 700 个）、智能体的能力选择器。
- **现象**：勾选框被拉成一个**细长的竖条**，勾选标记跟着一起被拉变形，
  看上去像个奇怪的锥形；外面还套着一层圆角胶囊（`.permission-choice`
  的 `border-radius: 999px`），观感更怪。
- **根因**：`admin.css` 里给**文本框、下拉框**准备的那套表单控件规则
  （`input, select, textarea { width: 100%; min-height: 42px; ... }`）
  把勾选框也一起套上了。`width: 100%` 在弹性容器里被压成各种宽度
  （实测 13px / 24px / 44px / 97px 不等），`min-height` 又把它拉到
  42–44px 高——浏览器就按这个尺寸去画原生勾选框，勾号自然被拉变形。
- **改法**：
  - 把这两类控件从表单控件规则里**排除**：
    `input:not([type="checkbox"]):not([type="radio"]), select, textarea`，
    三个主题各自的 `input` 规则同样排除；
  - 单独给勾选框 / 单选框一套固定尺寸：
    `width/height: 16px; min-height: 0; margin/padding: 0; border: 0;
    border-radius: 0; background: transparent; box-shadow: none;
    flex: none; accent-color: var(--color-accent);`。
- **顺带修好的**：外观页的主题单选框原本是 `width: 1px` + 通用规则的
  `min-height: 42px` → 实际变成 **1×44px 的细针**（还带 `border-radius: 50%`），
  正好也是「锥形」。现在它回到标准的 1×1 视觉隐藏写法。
- **实测**：14 个管理页 + 子视图共 **700 个**勾选框 / 单选框，全部
  **16×16px**，颜色取主题 accent；修复前同样的检查会报出 13×44、
  24×44、44×44、97×44 这一堆被拉变形的尺寸。
