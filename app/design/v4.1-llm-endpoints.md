# V4.1：数据库 LLM 接口配置与故障切换

> 状态：已实现。本版本把模型接口地址与 API Key 从运行期 Agent 内嵌配置提升为
> 独立的数据库配置表，并增加按优先级自动切换。

## 目标

原来的 Agent 表虽然有 `base_url` 和 `api_key_cipher`，但每个 Agent 只能配置一个
端点，且编排器重试时仍然回到同一个端点。主接口限流、余额不足或临时不可用时，
整个节点只能失败。

V4.1 增加全局 `llm_endpoint` 配置表：

- OpenAI 兼容地址与 API Key 由数据库管理；
- 可以配置多个启用项，`priority` 数值越小越先尝试；
- 每次节点执行前读取最新配置；
- 某接口在尚未输出内容前失败时，自动尝试下一个；
- API Key 加密落库，所有读取接口只返回 `has_api_key`。

## 数据模型

| 字段 | 说明 |
| --- | --- |
| `code` | 稳定唯一标识，用于管理接口定位 |
| `name` | 运维显示名 |
| `base_url` | OpenAI 兼容接口地址，必须以 `http://` 或 `https://` 开头 |
| `api_key_cipher` | Fernet 密文；空串表示本地无需鉴权的端点 |
| `priority` | 尝试顺序，越小越先，相同值按自增 id 稳定排序 |
| `enabled` | 停用项不参与运行期选择 |
| `version` | 配置修改版本号 |

`base_url` 不允许内嵌用户名或密码，避免凭据绕过独立加密字段进入日志。

## 管理接口

全部接口位于 `/api/llm-endpoints`，要求 `X-Admin-Key`：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/llm-endpoints` | 按优先级列出；`only_enabled=true` 只列启用项 |
| POST | `/api/llm-endpoints` | 新增配置 |
| GET | `/api/llm-endpoints/{code}` | 查询单条 |
| PUT | `/api/llm-endpoints/{code}` | 局部更新；省略 `api_key` 保持，显式空串则清除 |
| DELETE | `/api/llm-endpoints/{code}` | 删除 |

## 执行期选择

```text
节点执行
 └─ 读取 enabled=1 的 llm_endpoint
     └─ priority ASC, id ASC
         ├─ 尝试第 1 个
         │   ├─ 成功：本次节点后续工具轮次继续使用该接口
         │   └─ 请求失败且尚未输出：尝试下一个
         └─ 全部失败：向上返回最后一次接口错误
```

“尚未输出”是硬边界：

- 在建立流、首个 chunk 到达前失败，可以安全切换；
- 已向客户端发出 token 或 reasoning 后失败，不再切换。否则重放另一接口会让用户
  看到重复内容，也无法判断已经消费到哪一段。
- 用户取消和敏感内容拦截不属于接口故障，不触发切换。

## 兼容策略

数据库一旦存在任何配置，运行期**只使用启用项的有序列表**，不追加 Agent 内嵌地址。
管理员把全部配置停用意味着明确关闭模型调用，不会悄悄回退到旧地址。只有
`llm_endpoint` 表完全为空时，才回退到旧 Agent 的 `base_url` / `api_key_cipher`
单端点，保证升级期间已有数据继续工作。

HTTP Agent 创建/更新接口暂时保留 `base_url` 与 `api_key` 字段，作为旧客户端兼容面；
新部署应通过 `/api/llm-endpoints` 管理接口。

## 可观测性

- 切换时记录接口显示名和 code，不记录 Key。
- 最终异常仍由现有错误脱敏层处理。
- 每次节点执行重新加载配置，因此修改优先级或停用配置在下一个节点生效。
- 已在运行的节点使用自己的配置快照，不会在工具调用中途被热更新改变。

- 密钥加密落库；
- 启用项过滤与 priority 排序；
- 首个接口失败后切换；
- 已经输出内容后禁止切换；
- Alembic 与 ORM 表结构一致。
